Appointment manual script

  1. Start a fresh call. Wait for the greeting.
  2. Say: My patient ID is one zero zero one. My verification code is four two four two.
  3. Wait until verification finishes and the agent asks what you need.
  4. Say: I want to book an appointment for myself, the same patient I just verified.
  5. Ask: What appointment slots are available?
  6. If offered, say: Book October fifteenth, twenty twenty-six, at nine AM. If already taken, choose the offered two PM slot.
  7. Expect explicit appointment confirmation and courteous closure. Record the exact response, call ID and whether it asked for a different account.

Comparison call: repeat with the natural phrase “Can you schedule my appointment?” If only one wording fails, preserve both recordings. Do not provide another patient's details to bypass a wrong-account prompt.

Booking logic exists. The account-switch callback can clear verified state after an intent match; the focused diagnostic captured “I choose appointments” matching switch_patient. The code clears verification immediately, and the hosted run timed out. The exact original phone-call linkage remains unverified. Passing a scripted text booking does not prove phone success. Shared in-memory slots can be consumed by earlier calls and reset on restart; timezone, real scheduling and production persistence are not implemented.
